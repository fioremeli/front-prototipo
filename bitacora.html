Proceso

Bitácora de desarrollo

Registro del proceso del TP1: decisiones, problemas y ajustes realizados para que el código sea claro, mantenible y revisable.

  1. Etapa 1 · Organización

    Se definieron cinco perfiles y responsabilidades: Product & Frontend, Backend, UX/UI & QA, Data & Routing y DevOps & Docs. Se acordó que cada integrante mantiene su página, su script y sus commits.

  2. Etapa 2 · Arquitectura

    Un HTML por persona en la raíz, CSS dividido por responsabilidad en css/, JavaScript por módulo en js/ y todas las imágenes en img/. La separación permite subir el trabajo en commits pequeños y revisables.

  3. Etapa 3 · Identidad visual

    Paleta verde y azul (logística + tecnología), tipografías Orbitron para marca, Space Grotesk para títulos e IBM Plex Sans para lectura. Se diseñaron tema claro y oscuro con contraste verificado y variables CSS centralizadas.

  4. Etapa 4 · Accesibilidad y preferencias

    Skip-link, foco visible, etiquetas en formularios, alt descriptivo, ARIA, navegación completa con Tab y respeto por prefers-reduced-motion, prefers-contrast y prefers-color-scheme.

  5. Etapa 5 · Interactividad

    Portada: optimización de rutas y tema persistente. Cada perfil: una demo propia de su rol. Discos: patrón facade para cargar Spotify sólo bajo demanda.

  6. Etapa 6 · Próxima evolución

    TP2: backend real, datos de rutas, pruebas automatizadas y medición de Core Web Vitals.

Trabajo colaborativo

Gestión del repositorio y publicación

La bitácora no reemplaza al historial del repositorio: ambos registros se complementan. GitHub permite verificar cuándo y quién incorporó cada cambio, mientras que esta bitácora explica las decisiones, dificultades y criterios que llevaron a realizar esos cambios.

Participación distribuida

Cada integrante trabaja con su propia identidad de Git y aporta commits vinculados con su responsabilidad. Los avatares y recursos específicos de cada perfil se incorporan junto con el perfil correspondiente, mientras que los recursos globales quedan separados.

Commits y bitácora

Los commits registran la implementación técnica; la bitácora registra el razonamiento detrás de las decisiones. Por eso no se busca repetir una lista de commits, sino explicar el proceso y relacionarlo con las evidencias del repositorio.

Trabajo asincrónico

Como los horarios de los integrantes pueden no coincidir, se propone trabajar con ramas por integrante, actualizar antes de comenzar una sesión y utilizar Pull Requests para integrar cambios revisados en main.

Publicación y verificación

El proyecto se mantiene en un repositorio GitHub independiente y se publica en Vercel. Antes de la entrega se revisan navegación, responsive, teclado, foco, formularios y recursos multimedia en la versión publicada. La entrega distingue las pruebas realizadas de las verificaciones que todavía estén pendientes.

Documento de apoyo: el detalle del plan de commits se encuentra en docs/PLAN-DE-COMMITS.md.

Dificultades encontradas y cómo las resolvimos

Avatares de 89 a 153 KB y panel de 1200×1080

Se recomprimió a WebP: avatares 1200×1200 por debajo de 70 KB, panel 1200×1200 y pósters/discos por debajo de 40 KB. Se agregaron miniaturas de 400 px para las tarjetas, que antes descargaban la imagen completa.

Logo cuadrado (300×300) mostrado en una caja de 180×45

Se ajustó el tamaño a 44×44 px con width y height reales, eliminando el espacio vacío y evitando saltos de diseño.

Tab en el último enlace del menú devolvía el foco al título

Esa captura era una trampa de teclado. Se eliminó y se mantuvo el skip-link y el enlace «Volver arriba».

aria-labelledby apuntaba a un id inexistente en los perfiles

Se corrigió con ids únicos por sección (contacto-titulo) y se revisaron todos los formularios.

CSS con reglas repetidas y una tipografía cargada dos veces

Se dividió en nueve archivos por sección, se quitó el @import que bloqueaba el render y se fijó la versión de Devicon.

Las tarjetas «Conocé al resto del equipo» no reaccionaban al cursor como las de la portada

Se les aplicó la misma microinteracción (elevación, sombra y borde) con hover y foco de teclado, y se anuló con prefers-reduced-motion.

Animaciones y movimiento

Se agregó una sola animación de entrada (fadeInUp, 0,5 s, 12 px) dentro de prefers-reduced-motion: no-preference. No hay animaciones infinitas.

Landmark innecesario para los enlaces de GitHub

Se reemplazó <aside> por un <div> con su encabezado h3: los perfiles son parte del contenido del equipo, no un complemento.

Nombre accesible de las tarjetas

Se cambió «Abrir perfil de…» a «Ver perfil de …» para que el nombre accesible contenga el texto visible (WCAG 2.5.3, control por voz).

Botón de tema con anuncio duplicado

Se dejó sólo la etiqueta que describe la acción («Cambiar a modo claro / oscuro»).

aria-live en la demo dinámica

Se movió a role="status" sólo en el mensaje que cambia, evitando anunciar también el texto del botón.

CSS de la portada con reglas repetidas

Se fusionaron los bloques duplicados, se eliminaron reglas sin uso y se ordenó el archivo en seis secciones comentadas.

Modo oscuro y parpadeo inicial

Un script mínimo en el <head> aplica el tema antes de pintar y, sin elección guardada, se usa la preferencia del sistema.
